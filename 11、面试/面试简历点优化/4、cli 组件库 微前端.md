# CLi  前端工程化的理解

- 模块化
    - 大文件拆分为小文件 分而治之
    - AMD异步加载模块
- 组件化
    - UI组件
    - 逻辑组件
- 自动化
    - 自动化构建和部署
- 规范化
    - eslint检查
    - 代码规范

# 组件库
    - 标准性
    - 独立性
    - 复用性和易用性
    - 避免在组件中操作dom
    - 避免接收复杂参数
    - 合理的依赖关系  父组件不依赖子组件

# 微前端
 * 解决的问题
    - 拆分和细化庞大的spa应用
    - 整合历史系统
 * 微前端的核心价值
    - 技术栈无关，主框架不会限制和规定接入应用的技术栈
    - 独立开发 独立部署，接入的应用可以独立部署
    - 独立运行  接入的应用运行时独立运行  不共享状态
    - 升级框架  微前端可以很好的渐进式升级和重构老项目
# 微前端应用隔离
 - Css隔离  主应用于子应用使用webpack 的postcss  增加固定的前缀
 - Js隔离 使用沙箱机制（局部JS运行的时候，不会影响外部），主要是借助window.proxyAPI来实现
